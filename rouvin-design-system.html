The orange rule — the single most important constraint in this system

orange-500 on white is 3.05:1. That passes for non-text UI, and fails for text. White on orange-500 measures the same and fails identically. So:

→ Orange text on light uses orange-700 #D24E00 (4.35:1), or orange-500 only at 24px+ bold.
→ Orange fills carry ink-950 text, never white — that pairing measures 5.87:1 and passes.
→ Orange is never the sole signal for a state. Always pair it with an icon or a label.

Dark-on-orange is not a workaround, it is the right answer here: high-visibility livery — safety vests, load markings, road signage — is orange with black. Our users work in that world every day.

Info

Neutral system messages.

Why warning is mustard, not orange: brand orange already means "this is the action." If warning were also orange, a user could not tell a call-to-action from an alert. Every warning additionally carries the alert-triangle icon.

Do

Cancel

One primary action, clear descent to secondary and tertiary. The eye knows where to land in under a second.

Don't

Three competing emphases, plus white on orange at 3.05:1. Nothing is primary when everything is, and the last label is unreadable at speed.

Type rules

Never below 14px for body, never below 12px anywhere. Cap measure at 72 characters. Sentence case for headings, labels, buttons, and menus — ALL CAPS only for overline. tabular-nums on every numeric column. Never skip a heading level in the DOM to get a visual size — restyle instead.

No italics in the Console. The wordmark owns the italic; emphasis inside the product uses weight 600.

Iconography

Lucide is the single approved set — MIT licensed, consistent 24px grid, actively maintained. No mixing libraries, no marketplace one-offs, no emoji in product UI. Stroke is set to 1.75px rather than Lucide's 2px default: at dispatcher densities, 2px reads heavy against Plex Sans at 14px, while 1.75px sits correctly without losing the mark's confidence.

Icon rules

Every icon-only control needs an aria-label and a tooltip on hover and focus. Status icons always sit beside a text label — an icon is never the only carrier of meaning. Decorative icons next to their own label get aria-hidden="true".

Never rotate, flip, or recolour an icon to invent a new meaning, and never put icons on both sides of one button. Anything outside this inventory goes through a change request and enters the library properly.

Buttons

Five variants, three sizes, seven states. One primary action per view region — always. Tab through these to see the global focus ring.

Variants

Primary navy-700 / white — the one main action. Accent orange-500 / ink-950 — conversion moments only, max one per screen. Secondary white with slate-300 border. Tertiary for in-table and low-priority actions. Destructive always opens a confirmation that names the object.

Sizes

States

The loading state keeps the label so the button does not change width mid-flow. The verb on the button reappears in the confirmation: press Publish, get Published.

Forms

Labels always visible above the field — placeholders are examples, never labels. Validate on blur, not on keystroke. Error messages say what to do, not that something is wrong.

Start typing to search saved depots.
Enter a date on or after today.
Assign a vehicle first to enable this field.

Error copy standard

An error names what happened and what to do next, in the interface's voice. It does not apologise and it is never vague.

Write: "Enter a date on or after today."  ·  Not: "Invalid input" · "Oops! Something went wrong" · "Error 422".

Motion

Four durations, two easings, one hard rule: animate only transform and opacity. No bounce, no spring overshoot — this is operational software, and overshoot reads as instability.

TokenDurationEasingUse
motion-instant100mscubic-bezier(.4,0,.2,1)Hover, colour and border changes
motion-fast160mscubic-bezier(.4,0,.2,1)Tooltips, dropdowns, checkboxes
motion-base240mscubic-bezier(.2,.8,.2,1)Modals, drawers, accordions
motion-slow400mscubic-bezier(.2,.8,.2,1)Page transitions, route-line draw

prefers-reduced-motion: reduce is honoured throughout — movement is replaced by an opacity change of ≤ 100ms, never removed entirely. Motion is directional and truthful: a drawer that opens from the right closes to the right.

Accessibility standard

Target: WCAG 2.2 Level AA. This is a quality bar with a testing gate attached, not an aspiration. A feature does not ship until it passes all five checks below.

Non-negotiables

  • Text ≥ 4.5:1 · large text and UI components ≥ 3:1
  • Every function reachable by keyboard, in logical DOM order
  • Visible focus ring everywhere — outline:none without a replacement is a blocker
  • Semantic HTML first: button for actions, a for navigation, one h1 per page
  • Labels programmatically associated; errors use aria-describedby and aria-invalid
  • aria-live="polite" announces toasts, result counts, and async completions
  • Touch targets ≥ 44px, ≥ 48px on driver-facing screens
  • Usable at 200% zoom and reflows at 320px with no horizontal scroll
  • Colour is never the only means of conveying information
  • prefers-reduced-motion respected on every animation

Testing gate — all five, every feature

1. axe-core scan with zero critical or serious issues · 2. keyboard-only pass of the primary flow · 3. screen reader pass on NVDA and VoiceOver · 4. 200% zoom and 320px reflow check · 5. greyscale check — is the screen still fully understandable with colour removed?

Design QA checklist

Run before every release. Anything unticked is a blocker, not a nice-to-have. The full process — stages, Definition of Ready, Definition of Done, governance, and change control — lives in sop.md.

Visual & behaviour

  • All colours from the palette; contrast checked on the rendered pairing
  • Spacing uses only the 4px scale
  • One primary action per view region
  • Orange stays near 10% of the viewport
  • Icons uniform in size and stroke, drawn from the inventory
  • Logo clear space respected; correct variant for the background
  • All seven states verified on every control
  • Modal focus trap and Esc work; focus returns to the trigger
  • Destructive actions confirm and name the object

Content & resilience

  • Sentence case throughout; button verb matches the confirmation verb
  • No lorem ipsum, no placeholder names, no "Click here"
  • Errors explain what happened and what to do next
  • Numbers, dates, and units formatted consistently and localised
  • Longest realistic string does not break layout
  • Zero-state and 10,000-row states both render
  • Offline and slow-network paths tested
  • Layout tolerates +35% text expansion for localisation
  • Component added to Storybook with all states
